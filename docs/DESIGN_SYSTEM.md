# Design system

곳간지기의 색·타이포 기준입니다. 새 화면을 만들거나 기존 화면을 손볼 때
임의로 색과 폰트를 고르지 말고 이 문서의 토큰을 사용하세요.

> **구현 상태 (2026-09-05): 적용 완료.** `apps/web` 전체가 이 토큰을 사용합니다.
> 원시 Tailwind 팔레트 클래스(`blue-600`, `gray-500`, `bg-white` 등)와 하드코딩된
> 색상값은 코드베이스에 **하나도 남아 있지 않습니다**. 새 UI를 만들 때도 원시
> 팔레트를 다시 들이지 말고 아래 토큰 클래스를 쓰세요.
>
> 회귀 점검 (0이 나와야 정상):

## 1. 원칙

이 서비스는 README에 적힌 대로 **거래를 권하지 않고, 매매 신호를 주지 않고,
수익을 약속하지 않는** 기록 도구입니다. "지켜보는 사람"의 톤이지 "권유하는 앱"의
톤이 아닙니다. 디자인 판단이 갈릴 때는 이 기준으로 결정합니다.

- **강조색은 하나뿐이다.** 화면마다 다른 포인트 색을 만들지 않습니다.
- **의미색은 데이터 안에서만 쓴다.** 수익/손실/입출금 색은 숫자의 의미를 나타낼
  때만 쓰고, 버튼·헤더·브랜딩에는 쓰지 않습니다.
- **방향색과 상태색은 다른 축이다.** 상승/하락은 한국식(빨강/파랑),
  오류/성공은 만국 공통(빨강/초록)입니다. 둘을 같은 토큰으로 묶으면 시장 관례를
  바꿀 때 오류 메시지까지 파랗게 변합니다. `gain`/`loss`(방향)와
  `danger`/`success`(상태)를 절대 섞어 쓰지 마세요.
- **숫자는 정렬되어야 한다.** 금액·수량·등락률에는 항상 등폭 숫자를 씁니다.
- **쓰지 않는 톤:** 쨍한 파랑/보라 그라디언트(스타트업 랜딩 느낌), 네온·형광色
  (급등락 트레이딩 앱 느낌), 크림+테라코타 조합(장식적이고 따뜻해서 이 서비스의
  성격과 어긋남). 이 세 방향은 이전에 검토 후 명시적으로 반려된 방향입니다.

## 2. 색 토큰

라이트가 기본이고, 다크는 같은 이름의 값만 교체합니다. 컴포넌트는 항상 토큰을
거쳐 색을 쓰고, 미디어쿼리나 `[data-theme]` 블록 안에서 색을 직접 지정하지 않습니다.

| 토큰 | 라이트 | 다크 | 용도 |
| --- | --- | --- | --- |
| `bg` | `#F3F5F4` | `#141717` | 페이지 바탕. 순회색이 아니라 청록쪽으로 살짝 기운 종이빛 |
| `surface` | `#FFFFFF` | `#1C2021` | 카드·패널 |
| `surface-2` | `#EDF0EF` | `#232829` | 카드 안의 보조 영역, hover, 입력 폼 바탕 |
| `border` | `#DFE4E3` | `#303637` | 카드 테두리 |
| `border-soft` | `#E9EDEC` | `#282E2F` | 표의 행 구분선 |
| `ink` | `#15181A` | `#EAEDEC` | 본문 |
| `ink-muted` | `#5F676A` | `#9EA7A8` | 보조 설명 |
| `ink-faint` | `#666E71` | `#8A9496` | 라벨, 비활성, 종목코드. 시안의 `#939B9E`/`#6F797A`는 12–14px 표 헤더에서 대비 2.83:1/3.67:1로 WCAG AA 미달이라 실제 적용 시 조정했습니다 |
| `accent` | `#1D5560` | `#6DA9B4` | **유일한 강조색.** 기본 버튼, 링크, 차트 선 |
| `accent-tint` | `#E4EDEE` | `#1B3238` | 강조색 배경(칩 등) |
| `accent-ink` | `#17454E` | `#8CC0CA` | tint 위에 얹는 글자색 |
| `gain` | `#B03A2E` | `#E0776B` | **상승·수익 = 빨강**(한국식). 데이터 전용 |
| `gain-tint` | `#F9EAE8` | `#2F1D1B` | 상승 배지 배경 |
| `loss` | `#1552A0` | `#82B4E6` | **하락·손실 = 파랑**(한국식). 데이터 전용 |
| `loss-tint` | `#E8EEF7` | `#1A2432` | 하락 배지 배경 |
| `danger` | `#B03A2E` | `#E0776B` | 오류·삭제·최고 우선순위 경고. 방향과 무관 |
| `danger-tint` | `#F9EAE8` | `#2F1D1B` | 오류 박스 배경 |
| `success` | `#17714D` | `#4CBE8B` | 저장됨·접수 완료 같은 성공 상태 |
| `success-tint` | `#E6F2EC` | `#14271F` | 성공 박스 배경 |
| `flow` | `#8A6212` | `#CBA453` | **입출금** — 성과가 아님을 표시 |

| `inverse` | `#15181A` | `#0B0D0D` | 의도적으로 반전된 표면(코드블록, 차트 툴팁) |

`flow`(입출금)는 단순 장식이 아니라 **의미가 있는 색**입니다. 스냅샷 간 변동액에
입출금이 섞여 있으면 그 값은 투자 성과가 아니므로, 이 색으로 구분해 표시합니다.
자세한 배경은 `AGENTS.md`의 `gk_cash_flows` 설명을 참고하세요.

## 3. 타이포그래피

**폰트는 Pretendard 한 벌만 씁니다.** 판단일지와 데이터 화면을 다른 폰트로 나누지
않고, **굵기·크기·줄간격만으로** 구분합니다. Pretendard **가변 폰트**를 쓰기 때문에
`380`, `450` 같은 중간 굵기를 쓸 수 있고, 이게 두 화면을 가르는 핵심 장치입니다.

### 두 가지 조판 세팅

| | 데이터 화면 (곳간·스냅샷·포지션) | 판단일지 화면 |
| --- | --- | --- |
| 본문 굵기 | `400` | **`380`** |
| 본문 크기 | `15px` | `16.5px` |
| 줄간격 | `1.55` | **`1.88`** |
| 자간 | 숫자 `-0.02em` | 기본 |
| 숫자 | `tabular-nums` 고정 | 본문에 자연스럽게 섞임 |
| 한 줄 길이 | 제한 없음(표) | **44자 내외** |

목적: 데이터 화면은 "숫자가 주인공인 조판", 판단일지는 "읽는 글의 조판".
판단일지는 README상 *판단 기준을 사전에 공개하는* 글이므로 데이터 표처럼 보이면 안 됩니다.

### 굵기 사용처

| 굵기 | 용도 |
| --- | --- |
| `380` | 판단일지 본문 |
| `450` | 판단일지 요약(리드문) |
| `400` | 데이터 화면 본문 |
| `600` | 금액·숫자 강조, 섹션 제목, 표 헤더 |
| `700` | 화면 제목(`h1`) |

### 숫자 표기 규칙

금액·수량·등락률·날짜가 세로로 정렬되어야 하는 곳(표, 카드의 큰 숫자)에는
반드시 `font-variant-numeric: tabular-nums`(Tailwind `tabular-nums`)를 적용합니다.
정렬이 필요 없는 판단일지 본문 속 숫자에는 적용하지 않습니다.

## 4. 형태

- 모서리: 카드 `10px`, 버튼·입력 `8px`, 배지·칩 `999px`. 모든 요소에 큰 라운드를
  일괄 적용하지 않습니다.
- 그림자: 진한 그림자 대신 얇은 테두리 + 아주 옅은 그림자.
  - `shadow-sm`: `0 1px 2px rgba(21,24,26,0.04)` — 일반 카드
  - `shadow-md`: `0 1px 3px rgba(21,24,26,0.05), 0 14px 30px -18px rgba(21,24,26,0.16)` — 화면 최상단 요약 카드
  - 다크에서는 두 값 모두 `rgba(0,0,0,0.3~0.6)` 계열로 교체합니다.
- 좁은 화면: 표는 우선순위 낮은 칸을 `hidden sm:table-cell`로 숨기고, 셀 여백을
  `px-2 sm:px-4`로 줄입니다. 가로 스크롤로 칸이 잘려 보이지 않게 하는 것이 원칙입니다.
  (실제로 `관리` 칸이 화면 밖으로 밀려 안 보이던 버그가 있었습니다.)

## 5. 사용법

Tailwind 클래스 이름은 CSS 변수(`--gk-*`)를 가리킵니다. 정의는
`apps/web/src/index.css`, 클래스 등록은 `apps/web/tailwind.config.js`입니다.

| 토큰 | 클래스 예 |
| --- | --- |
| 배경 | `bg-bg`, `bg-surface`, `bg-surface-2` |
| 글자 | `text-ink`, `text-ink-muted`, `text-ink-faint` |
| 선 | `border-line`, `border-line-soft`, `divide-line-soft` |
| 강조 | `bg-accent`, `text-accent`, `bg-accent-tint`, `text-accent-ink`, `text-accent-contrast` |
| 방향(한국식) | `text-gain`(상승·빨강), `text-loss`(하락·파랑), `bg-gain-tint`, `bg-loss-tint` |
| 상태 | `text-danger`, `bg-danger-tint`(오류·삭제), `text-success`, `bg-success-tint`(성공) |
| 입출금 | `text-flow`, `bg-flow-tint` |
| 반전 표면 | `bg-inverse`, `text-inverse-ink` |

판단일지 조판은 `MarkdownContent`의 `variant` prop으로 전환합니다 —
`variant="prose"`(본문), `variant="lead"`(요약). 기본값은 카드·미리보기에 쓰는
압축 세팅입니다.

### 적용하면서 걸렸던 함정

새로 UI를 만들 때 같은 곳에 다시 빠지기 쉬운 것들입니다.

- **`ch`는 한글 폭이 아닙니다.** `ch`는 숫자 `0` 글리프의 폭(여기선 약 10px)이라,
  `44ch`로 잡으면 한글은 44자가 아니라 **31자**만 들어갑니다. 그래서 본문 폭은
  `em`(한글 1자 ≈ 1em에 가까움)으로 잡아 `38em` = 실측 44자입니다.
- **`color-scheme`이 없으면 다크에서 폼이 깨집니다.** 이게 없으면 브라우저가
  `select`·`input[type=number]`를 라이트 기준(흰 배경)으로 그리는데 글자색은
  토큰(밝은색)을 따라가서 **흰 배경에 흰 글자**가 됩니다. `:root`에
  `color-scheme: light`, 다크 블록에 `color-scheme: dark`가 반드시 필요합니다.
- **SVG 프레젠테이션 속성에는 `var()`가 안 먹습니다.** `stroke="var(--gk-accent)"`는
  적용되지 않습니다. 부모에 `style={{ color }}`로 CSS 선언을 주고 도형은
  `stroke="currentColor"`로 상속받게 하세요 (`Sparkline.tsx` 참고).
- **폰트는 dynamic-subset으로 넣습니다.** 단일 파일(약 2MB) 대신 유니코드 범위별로
  쪼갠 빌드를 import 하면, 실제 페이지 로드에서는 필요한 범위만 받습니다
  (측정값: 92개 중 11개 · 77KB).
- **상승은 빨강, 하락은 파랑입니다(한국식).** 서양식 초록/빨강이 아닙니다.
  포지션 표·스냅샷 증감·시장 지수·MACD·RSI·판단일지 BUY/SELL 배지까지 전부
  이 규칙을 따릅니다.
- **오류를 `loss`로 칠하지 마세요.** `loss`는 이제 파랑이라 오류 메시지가
  파랗게 나옵니다. 오류·삭제는 `danger`, 성공은 `success`입니다. 초록은 더 이상
  "수익"이 아니라 "성공"을 뜻합니다.
