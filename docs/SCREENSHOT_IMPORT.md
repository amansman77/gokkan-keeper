# 스크린샷으로 곳간 맞추기 (설계안)

상태: **P1 구현** (판독 엔진·API·DB, 2026-10-24). P2 화면·P3 환전내역은 다음 단계.

삼성증권은 개인용 OpenAPI가 없어 토스(`toss-sync.mjs`)처럼 자동 동기화할 수
없다. 대신 증권사 앱 스크린샷을 웹에 올리면, Mac Studio의 로컬 OCR(Indra OCR)이
판독하고, 검증을 통과한 결과만 사용자가 승인해 포지션·스냅샷·입출금에
반영한다. 2026-10-24에 수작업으로 한 대사(reconciliation)를 그대로 기능으로
옮기는 것이 목표다.

## 1. 범위

| 단계 | 화면 | 반영 대상 |
| --- | --- | --- |
| P1 | 삼성 `주식잔고/손익`(국내), `해외주식잔고/손익`, `예수금`, 해외 `외화잔고` | 포지션 수량·평균단가, 스냅샷 |
| P2 | 위 결과의 검토·승인 화면 | 저장 |
| P3 | 삼성 `환전내역` | 짝지은 입출금(원화 곳간 출금 + 달러 곳간 입금) |

범위 밖: 토스(이미 API 동기화), 업비트(API 동기화), 임의 증권사 레이아웃.
판독기는 화면 종류별로 명시적으로 추가한다.

## 2. 흐름

```text
[웹] POST /imports {granaryId}                         → draft 작업 (소유자 세션 전용)
     PUT  /imports/:id/images/:seq {mime, data(base64)} → 이미지 1장씩 (≤1.5MB, 최대 12장)
     POST /imports/:id/submit                          → queued
[Mac] ocr-import (launchd, 1분 간격, 자동화 범위 imports:process)
     GET  /imports/next                → 가장 오래된 작업을 10분 임대 (작업 id + 이미지 번호만)
     GET  /imports/:id/images/:seq     → 이미지 바이트
     Indra OCR (오프라인, HF_HUB_OFFLINE=1) → 줄 단위 텍스트 + 좌표
     POST /imports/:id/ocr {pages}     → 서버가 해석·검증 → parsed, 이미지 즉시 삭제
     POST /imports/:id/fail {error}    → failed, 재제출을 위해 이미지 24시간 보관
[웹] GET  /imports/:id                 → 판독 결과와 제안
     POST /imports/:id/apply {zeroMissing?, createNew?} → 검증을 모두 통과한 경우에만 반영
     POST /imports/:id/discard
```

설계에서 바뀐 점:
- **Mac은 OCR만, 해석은 서버에서** 한다. 표 재구성·숫자 교정·검증 로직이
  저장소(`apps/api/src/services/screenshot-import/`) 안에 있어 테스트와 리뷰를
  거친다. Mac 작업은 이미지를 읽어 줄 단위 결과만 보낸다.
- 업로드는 **base64 JSON**이다. API가 브라우저 요청에 JSON 본문만 허용하는
  기존 보안 정책을 그대로 유지하기 위해서다. 원본 해상도 JPEG(품질 85, 장당
  약 240KB)는 PNG와 같은 판독 결과를 냈고, 해상도를 줄이면 오류가 생겼다.
- Mac 작업은 작업 결과·곳간을 볼 수 없다. 이미지 읽기와 결과 보고만 한다.

## 3. 저장 구조 (마이그레이션 0021)

- `gk_import_jobs`: `id`, `granary_id`, `status`(`queued` → `processing` →
  `parsed` | `failed` → `applied` | `discarded`), `result_json`, `error`,
  `created_at`, `updated_at`, `expires_at`.
- `gk_import_images`: `job_id`, `seq`, `mime`, `bytes`(BLOB), `sha256`.
  판독 결과를 받는 즉시 삭제한다. 실패해도 `expires_at`(24시간)에 정리한다.
- 이미지 1장 ≤ 1.5MB(D1 행 한도 2MB 아래), 작업당 ≤ 12장. 서버에서
  `isValidImage()`로 형식을 확인한다.
- `gk_import_accounts`: 곳간 ↔ 계좌 끝자리. 첫 반영 때 화면의 계좌로 연결되고,
  이후 다른 계좌의 화면은 검증에서 거부된다.
- 세 표 중 작업·이미지 표는 일회성 데이터라 `scripts/data-backup.mjs`의 백업
  대상에서 제외한다.

## 4. 판독기

Indra OCR의 줄 단위 결과(텍스트 + 좌표)를 쓴다. 텍스트 순서는 가끔 섞이므로
**좌표로 행과 열을 재구성**한다.

1. **화면 분류**: 제목·탭 문구(`주식잔고/손익` + 국내/해외, `예수금`,
   `외화잔고`, `환전내역`)와 계좌번호(`7078921216-01` 등)를 찾는다.
2. **행 묶기**: 종목 목록 영역을 y좌표로 묶어 종목 1개 = 2줄 블록으로 본다.
   열은 x좌표로 나눈다. 국내는 `종목명 | 평가손익/수익률 | 보유수량/평가금액`,
   해외는 `종목명/종목코드 | 평가손익/수익률 | 보유수량/평가금액`.
3. **숫자 정규화**: 원화는 정수, 달러는 소수점 2~4자리. 상단 합계에서 보인
   `-287.463원`(쉼표 → 마침표), `-597%`(소수점 누락) 같은 오류는 통화별
   자릿수 규칙과 행 합계로 교정한다.
4. **종목 매칭**: 해외는 종목코드로 정확히 매칭한다. 국내는 이름이 틀릴 수
   있으므로(`NHN벅스` → `NHN브`) 기존 포지션 이름과의 편집거리, 그리고
   "수량 × 현재 시세 ≈ 평가금액"으로 매칭한다. 애매하면 사용자에게 고르게 한다.
5. **겹친 스크린샷**: 같은 (종목, 수량, 평가금액)은 한 번만 센다.

## 5. 검증 (통과해야 승인 가능)

| 검증 | 기준 | 실패 시 |
| --- | --- | --- |
| 손익 합계 | 종목별 평가손익의 합 = 화면 상단 평가손익 (원화 ±1원, 달러 ±0.01) | "스크린샷이 빠졌거나 잘못 읽은 종목이 있어요" + 차이 금액 |
| 평가금액 합계 | 해외: 종목 평가금액 합 = `주식평가금액` | 같음 |
| 계좌 일치 | 모든 이미지의 계좌번호가 같고, 곳간에 연결된 계좌와 같음 | 업로드 거부 |
| 예수금 존재 | 예수금 화면 1장 포함 | 스냅샷 없이 포지션만 반영할지 묻기 |

경고(승인은 가능):
- **설명 안 되는 예수금 변화**: 직전 스냅샷 대비 예수금 감소 − 매수 추정액 −
  기록된 입출금이 남으면 "환전이나 출금이 있었나요?"
- 곳간에는 있는데 화면에 없는 종목 (매도했나요?)
- 처음 보는 종목 (새 포지션으로 등록할지)

## 6. 검토 화면

- 바뀐 포지션만 표로 표시: 수량, 평균단가(= (평가금액 − 평가손익) ÷ 수량)
- 새 스냅샷: 총액 = 주식 평가금액 + 예수금, 기준일 = 스크린샷 날짜
- 검증 결과 배지와 경고 목록
- 원본 스크린샷은 **보여주지 않는다**. 판독 후 이미 삭제되었기 때문이다.
  대신 읽은 값과 그 값이 나온 화면 번호를 표시한다.

## 7. 반영

`POST /imports/:id/apply`가 기존 레포지토리를 통해 한 트랜잭션으로 저장한다.
- 포지션: 수량·평균단가 갱신, 새 종목 생성(사용자 선택 시)
- 스냅샷: 같은 날짜가 있으면 갱신
- 메모: `스크린샷 판독 (평가손익 …)`
- P3: 환전내역 → 원화 곳간 `WITHDRAWAL` + 달러 곳간 `DEPOSIT`, 이미 있는 건은 제외

## 8. 개인정보와 보안

- 이미지는 **곶간 지기 D1과 Mac 안에서만** 처리하고 외부 AI 서비스로 보내지 않는다.
- 판독이 끝나면 즉시 삭제하고, 실패해도 24시간 뒤 삭제한다. 로그에 이미지나
  계좌번호를 남기지 않는다. 결과 JSON의 계좌번호는 끝 4자리만 저장한다.
- 업로드·조회·적용은 소유자 세션 전용이다. Mac 작업은 새 자동화 범위
  `imports:process`만 가지며, `queued` 이미지 읽기와 결과 쓰기만 할 수 있다.
- 모델 라이선스(OpenRAIL-M)는 개인 사용 조건으로 쓴다.

## 9. 결정 사항 (2026-10-24)

1. **스냅샷 `profitLoss`**: 이 기능부터 화면 상단의 **실제 평가손익**을 기록한다
   (용어집 정의와 일치). 과거 수동 기록(주식 평가금액을 넣어 둔 것)의 정리는 별도로 한다.
2. **곳간 ↔ 계좌 연결**: 사용한다. 첫 반영 시 자동 연결.
3. **실패한 작업의 이미지**: 재판독을 위해 24시간 보관한다.

| P1 | 마이그레이션, `/imports` API, Mac 작업, 삼성 국내·해외·예수금 판독기 | 2026-10-24 스크린샷 20여 장으로 판독 결과가 수작업 대사와 100% 일치 |
| P2 | 업로드·검토·적용 화면 | 브라우저 테스트로 업로드 → 검증 실패 표시 → 승인 → 저장 확인 |
| P3 | 환전내역 → 입출금 | 9/21·9/28·10/13 환전 3건 재현, 중복 생성 없음 |

저장소가 공개되어 있으므로 실제 스크린샷이나 그 OCR 결과는 커밋하지 않는다.
테스트(`apps/api/scripts/checks/screenshot-import.test.ts`, `integration/imports.test.ts`)는
삼성 화면의 좌표 배치를 흉내 낸 합성 페이지(`screenshot-fixtures.ts`)를 쓰고, 실제
스크린샷에서 겪은 오류(쉼표→마침표, 스크롤바 숫자, 누락된 수량, 깨진 종목명, 뒤섞인
읽기 순서)를 재현한다. 실제 스크린샷 대조는 Mac에서만 한다. 2026-10-24 스크린샷
18장으로 가계 국내 20종목·가계 해외 13종목·비상금 국내 17종목이 수작업 대사와 일치했고,
보유 화면이 한 장뿐이던 비상금 해외는 합계 검증에서 정확히 거부됐다.
