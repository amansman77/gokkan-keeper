# Design system

곳간지기의 색·타이포 기준입니다. 새 화면을 만들거나 기존 화면을 손볼 때
임의로 색과 폰트를 고르지 말고 이 문서의 토큰을 사용하세요.

> **⚠️ 구현 상태 (2026-09-05): 이 문서는 합의된 목표 디자인이고, 코드에는 아직 반영되지 않았습니다.**
>
> 현재 `apps/web`은 Tailwind 기본 팔레트(`blue-600`, `gray-*` 등)와 시스템 폰트를
> 그대로 쓰고 있습니다. `tailwind.config.js`의 `theme.extend`는 비어 있고,
> Pretendard도 아직 번들되어 있지 않습니다. **아래의 `accent`/`gain` 같은 이름은
> 지금 Tailwind 클래스로 존재하지 않으니 `bg-accent` 같은 클래스를 쓰면 조용히
> 아무 스타일도 적용되지 않습니다.** 적용 작업을 할 때는 "구현 절차" 절을 먼저 읽으세요.
> 마이그레이션이 끝나면 이 경고 블록을 지우고 상태를 갱신하세요.

## 1. 원칙

이 서비스는 README에 적힌 대로 **거래를 권하지 않고, 매매 신호를 주지 않고,
수익을 약속하지 않는** 기록 도구입니다. "지켜보는 사람"의 톤이지 "권유하는 앱"의
톤이 아닙니다. 디자인 판단이 갈릴 때는 이 기준으로 결정합니다.

- **강조색은 하나뿐이다.** 화면마다 다른 포인트 색을 만들지 않습니다.
- **의미색은 데이터 안에서만 쓴다.** 수익/손실/입출금 색은 숫자의 의미를 나타낼
  때만 쓰고, 버튼·헤더·브랜딩에는 쓰지 않습니다.
- **숫자는 정렬되어야 한다.** 금액·수량·등락률에는 항상 등폭 숫자를 씁니다.
- **쓰지 않는 톤:** 쨍한 파랑/보라 그라디언트(스타트업 랜딩 느낌), 네온·형광色
  (급등락 트레이딩 앱 느낌), 크림+테라코타 조합(장식적이고 따뜻해서 이 서비스의
  성격과 어긋남). 이 세 방향은 이전에 검토 후 명시적으로 반려된 방향입니다.

## 2. 색 토큰

라이트가 기본이고, 다크는 같은 이름의 값만 교체합니다. 컴포넌트는 항상 토큰을
거쳐 색을 쓰고, 미디어쿼리나 `[data-theme]` 블록 안에서 색을 직접 지정하지 않습니다.

| 토큰 | 라이트 | 다크 | 용도 |
| --- | --- | --- | --- |
| `bg` | `#F3F5F4` | `#141717` | 페이지 바탕. 순회색이 아니라 청록쪽으로 살짝 기운 종이빛 |
| `surface` | `#FFFFFF` | `#1C2021` | 카드·패널 |
| `surface-2` | `#EDF0EF` | `#232829` | 카드 안의 보조 영역, hover, 입력 폼 바탕 |
| `border` | `#DFE4E3` | `#303637` | 카드 테두리 |
| `border-soft` | `#E9EDEC` | `#282E2F` | 표의 행 구분선 |
| `ink` | `#15181A` | `#EAEDEC` | 본문 |
| `ink-muted` | `#5F676A` | `#9EA7A8` | 보조 설명 |
| `ink-faint` | `#939B9E` | `#6F797A` | 라벨, 비활성, 종목코드 |
| `accent` | `#1D5560` | `#6DA9B4` | **유일한 강조색.** 기본 버튼, 링크, 차트 선 |
| `accent-tint` | `#E4EDEE` | `#1B3238` | 강조색 배경(칩 등) |
| `accent-ink` | `#17454E` | `#8CC0CA` | tint 위에 얹는 글자색 |
| `gain` | `#17714D` | `#4CBE8B` | 수익 — 데이터 전용 |
| `gain-tint` | `#E6F2EC` | `#14271F` | 수익 배지 배경 |
| `loss` | `#B03A2E` | `#E0776B` | 손실 — 데이터 전용 |
| `loss-tint` | `#F9EAE8` | `#2F1D1B` | 손실 배지 배경 |
| `flow` | `#8A6212` | `#CBA453` | **입출금** — 성과가 아님을 표시 |
| `flow-tint` | `#F5EEDD` | `#2D2717` | 입출금 배지 배경 |

입출금이 섞여 있으면 그 값은 투자 성과가 아니므로, 이 색으로 구분해 표시합니다.
자세한 배경은 `AGENTS.md`의 `gk_cash_flows` 설명을 참고하세요.

## 3. 타이포그래피

**폰트는 Pretendard 한 벌만 씁니다.** 판단일지와 데이터 화면을 다른 폰트로 나누지
않고, **굵기·크기·줄간격만으로** 구분합니다. Pretendard **가변 폰트**를 쓰기 때문에
`380`, `450` 같은 중간 굵기를 쓸 수 있고, 이게 두 화면을 가르는 핵심 장치입니다.

### 두 가지 조판 세팅

| | 데이터 화면 (곳간·스냅샷·포지션) | 판단일지 화면 |
| --- | --- | --- |
| 본문 굵기 | `400` | **`380`** |
| 본문 크기 | `15px` | `16.5px` |
| 줄간격 | `1.55` | **`1.88`** |
| 자간 | 숫자 `-0.02em` | 기본 |
| 숫자 | `tabular-nums` 고정 | 본문에 자연스럽게 섞임 |
| 한 줄 길이 | 제한 없음(표) | **44자 내외** |

목적: 데이터 화면은 "숫자가 주인공인 조판", 판단일지는 "읽는 글의 조판".
판단일지는 README상 *판단 기준을 사전에 공개하는* 글이므로 데이터 표처럼 보이면 안 됩니다.

### 굵기 사용처

| 굵기 | 용도 |
| --- | --- |
| `380` | 판단일지 본문 |
| `450` | 판단일지 요약(리드문) |
| `400` | 데이터 화면 본문 |
| `600` | 금액·숫자 강조, 섹션 제목, 표 헤더 |
| `700` | 화면 제목(`h1`) |

### 숫자 표기 규칙

금액·수량·등락률·날짜가 세로로 정렬되어야 하는 곳(표, 카드의 큰 숫자)에는
반드시 `font-variant-numeric: tabular-nums`(Tailwind `tabular-nums`)를 적용합니다.
정렬이 필요 없는 판단일지 본문 속 숫자에는 적용하지 않습니다.

## 4. 형태

- 모서리: 카드 `10px`, 버튼·입력 `8px`, 배지·칩 `999px`. 모든 요소에 큰 라운드를
  일괄 적용하지 않습니다.
- 그림자: 진한 그림자 대신 얇은 테두리 + 아주 옅은 그림자.
  - `shadow-sm`: `0 1px 2px rgba(21,24,26,0.04)` — 일반 카드
  - `shadow-md`: `0 1px 3px rgba(21,24,26,0.05), 0 14px 30px -18px rgba(21,24,26,0.16)` — 화면 최상단 요약 카드
  - 다크에서는 두 값 모두 `rgba(0,0,0,0.3~0.6)` 계열로 교체합니다.
- 좁은 화면: 표는 우선순위 낮은 칸을 `hidden sm:table-cell`로 숨기고, 셀 여백을
  `px-2 sm:px-4`로 줄입니다. 가로 스크롤로 칸이 잘려 보이지 않게 하는 것이 원칙입니다.
  (실제로 `관리` 칸이 화면 밖으로 밀려 안 보이던 버그가 있었습니다.)

## 5. 구현 절차 (미완료)

적용할 때 이 순서로 진행하세요.

1. **Pretendard 번들.** `pnpm --filter web add pretendard` 후 가변 폰트를 로컬에서
   import 합니다. **CDN `<link>`를 쓰지 마세요** — 외부 의존성이 생기고, 이 저장소는
   자체 호스팅 원칙입니다. `apps/web/src/index.css`의 `body` 폰트 스택을 교체하고
   `font-variation-settings`로 굵기를 제어합니다.
2. **토큰 정의.** 위 색표를 CSS 변수로 `index.css`에 넣되, 라이트는 맨 `:root`,
   다크는 `@media (prefers-color-scheme: dark)`와 `:root[data-theme="dark"]` 양쪽에
   정의합니다(둘 중 하나만 있으면 특정 조합에서 색이 깨집니다).
3. **Tailwind 연결.** `tailwind.config.js`의 `theme.extend.colors`에 CSS 변수를
   참조하는 이름(`accent`, `gain`, `loss`, `flow`, `ink` 등)을 등록해야
   `bg-accent` 같은 클래스가 생성됩니다. 이 단계를 건너뛰면 클래스가 조용히 무시됩니다.
4. **화면 치환.** 현재 하드코딩된 Tailwind 기본색을 토큰으로 바꿉니다. 대응표:
   - `blue-600`(기본 버튼·링크) → `accent`
   - `green-600`/`green-50` → `gain`/`gain-tint`
   - `red-600`/`red-50` → `loss`/`loss-tint`
   - `amber-700`/`amber-50`(입출금 배지) → `flow`/`flow-tint`
   - `gray-900`/`gray-600`/`gray-400` → `ink`/`ink-muted`/`ink-faint`
   - `bg-slate-50`(App 배경) → `bg`
5. **판단일지 조판 분리.** `JudgmentDiaryDetail.tsx`와 `MarkdownContent.tsx`에
   위 "판단일지 화면" 세팅(380 굵기·16.5px·1.88·44자)을 적용합니다.
6. 마친 뒤 이 문서 상단의 구현 상태 경고를 갱신합니다.
